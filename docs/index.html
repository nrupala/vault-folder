Vault Folder

Your files, encrypted before they ever leave your machine — in any folder, on any storage.

Free forever Apache License 2.0 Zero dependencies No account · No telemetry AES-256-GCM

Vault Folder turns an ordinary folder into a zero-knowledge vault. Put the folder on your hard drive, a file server, a NAS — or inside the synced folder of Google Drive, OneDrive, Dropbox, iCloud or Syncthing — and everything in it is ciphertext before the sync client, the server, or the provider ever sees it. They store it. Only you can read it.

Quick start

Requires Node.js 18+. There is nothing to install — no dependencies.

# create a vault inside your cloud-synced folder
node bin/vaultfolder.mjs init  ~/Google\ Drive/MyVault

# add files
node bin/vaultfolder.mjs add   ~/Google\ Drive/MyVault  ~/Documents/taxes-2026.pdf

# names exist only inside the encrypted manifest
node bin/vaultfolder.mjs list  ~/Google\ Drive/MyVault

# restore a file
node bin/vaultfolder.mjs get   ~/Google\ Drive/MyVault  taxes-2026.pdf  ~/Restored

On init you receive a recovery key, shown once and never stored. Write it down. If you lose both your password and the recovery key, the vault cannot be opened — by you, by us, or by anyone. That is the point, and it is also the price.

How it works

Envelope encryption

A random 256-bit vault key encrypts everything. It is wrapped twice — by your password (PBKDF2-SHA-256, 600,000 rounds) and by your recovery key — and never stored.

A key per file

Every file gets its own random key, wrapped by the vault key. One file's damage never touches another's.

Tamper-evident chunks

Contents are sealed in 4 MiB AES-256-GCM chunks, each bound to its position. Tampering, truncation and reordering fail loudly on read.

Hidden names

File names live only inside the encrypted manifest. The vault folder shows an outsider nothing but opaque ids.

The full byte-level format is specified in the repository's FORMAT.md — anyone can write an independent reader.

What the provider can still see

Honesty over pitch: whoever holds your vault can see that a vault exists, roughly how much ciphertext it holds, and when it changes. They cannot see file names, file contents, or what any file is.
